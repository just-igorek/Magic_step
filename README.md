# Magic Step — бой отрядов

Курсовой проект (Елунин Игорь): пошаговая тактическая игра на клеточном поле.
Здесь — лабораторные работы по ООП и управлению памятью. Сейчас в проекте три класса
предметной области:

| Класс | Роль |
|---|---|
| `Unit` | Боевая единица: здоровье, позиция, получение урона и лечение |
| `Cell` | Клетка поля; наблюдает за юнитом, который на ней стоит |
| `Battlefield` | Поле из клеток; создаёт клетки сам и ими владеет |

Связи между классами:

- **Композиция** `Battlefield` → `Cell`: поле создаёт клетки в конструкторе и уничтожает вместе с собой.
- **Агрегация** `Cell` → `Unit`: юнит создаётся снаружи и живёт независимо от клетки и поля.
- **Проверка правила**: в занятую клетку нельзя поставить второго юнита.

## Версии проекта

- `include/`, `src/`, `main.cpp` — C++17, умные указатели (ЛР 3, часть 2).
- `csharp/` — перенос на C# (ЛР 3, часть 1), собственный `README.md` с командами.

## Сборка и запуск (C++)

Нужен `g++` с поддержкой C++17. Из корня репозитория:

```bash
mkdir -p build
g++ -std=c++17 -Wall -Wextra -Iinclude main.cpp src/battle/*.cpp -o build/battle
./build/battle
```

Windows (PowerShell): `.\build\battle.exe`. Папка `build/` в репозиторий не попадает.

## Таблица владения (C++)

| Где был указатель | На что указывает | Кто владеет | Заменяется на | Почему |
|---|---|---|---|---|
| `Battlefield::m_cells` (`Cell***`, внешний массив) | массив строк поля | `Battlefield`, один владелец | `std::unique_ptr<CellRow[]>` | Массив принадлежит только полю и живёт ровно столько же |
| `m_cells[y]` (`Cell**`, строки) | массив клеток строки | `Battlefield`, один владелец | `std::unique_ptr<std::unique_ptr<Cell>[]>` (`CellRow`) | Каждая строка принадлежит только полю |
| `m_cells[y][x]` (`Cell*`) | клетка | `Battlefield`, один владелец | `std::unique_ptr<Cell>`, создаётся через `make_unique` | Композиция: клетки не нужны никому, кроме поля |
| `Cell::m_unit` (`Unit*`) | юнит на клетке | не клетка; юнитом владеет код, который его создал | `std::weak_ptr<Unit>` | Агрегация: клетка только наблюдает; если юнит уничтожен, клетка сама становится пустой, а не хранит висячий указатель |
| `Battlefield::PlaceUnit(Unit*)`, `Cell::SetUnit(Unit*)` (параметр) | юнит | не функция | `const std::shared_ptr<Unit>&` | Функция сохраняет наблюдателя на юнита, а `weak_ptr` создаётся только из `shared_ptr`, поэтому «голый» указатель уже не подходит |
| `Cell::GetUnit()` (возврат `Unit*`) | юнит на клетке | не клетка | `std::shared_ptr<Unit>` (результат `lock()`) | Пока вызывающий пользуется юнитом, тот гарантированно жив; пустой указатель — клетка пуста |
| `Battlefield::GetCell()` (возврат `Cell*`) | клетка | `Battlefield` | `Cell&` (бросает `std::out_of_range`) | Владения нет, указатель возвращать нельзя; «вне поля» теперь исключение, а не `nullptr` |
| `main`: `hero`, `enemy` (`Unit*`) | юниты | `main`, плюс наблюдатели в клетках | `std::shared_ptr<Unit>` через `make_shared` | Клетки наблюдают за юнитами через `weak_ptr`, а он требует `shared_ptr` на стороне владельца |
| `main`: `dynamicUnit` (`Unit*`) | один юнит | блок в `main`, один владелец | `std::unique_ptr<Unit>` | Единственный владелец, объект нужен только в блоке |
| `main`: `squad` (`Unit*` на `new Unit[2]`) | массив юнитов | блок в `main`, один владелец | `std::unique_ptr<Unit[]>` | Один владелец; `delete[]` вызовется сам |
| `main`: `squadPtr` (`Unit**`) | массив указателей на юнитов | блок в `main`, один владелец | `std::unique_ptr<Unit> squadPtr[2]` | Каждый юнит — свой единственный владелец |
| Параметры `PrintUnitByPtr(const Unit*)` | юнит | не функция | остаётся обычным указателем | Функция только смотрит, нигде не сохраняет (допустимо по условию) |

Где какой указатель:

- `unique_ptr` — клетки поля (композиция), а также единоличные объекты и массивы в `main`;
- `shared_ptr` — юниты, за которыми наблюдают клетки;
- `weak_ptr` — ссылка клетки на юнита (агрегация).

Поле-объект по значению (композиция из ЛР 2) менять не пришлось: в проекте таких полей нет, потому что
клетки создаются динамически по размерам, известным только во время выполнения.

В проекте нет ни одного `new` и ни одного `delete`.
